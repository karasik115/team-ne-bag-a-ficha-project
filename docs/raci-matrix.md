# Матрица распределения ответственности

**Команда:** «Не баг, а фича», бригада № 1.

- **R (Responsible)** выполняет задачу.
- **A (Accountable)** отвечает за конечный результат.
- **C (Consulted)** консультирует по задаче.
- **I (Informed)** получает информацию о ходе и результате.
- **R/A** означает совмещение исполнения и ответственности за результат одним участником.

Для каждой задачи назначен один A и как минимум один R.

## Матрица первого этапа из отчёта № 1

Распределение букв сохранено из исходной матрицы. Исправлены только опечатки в названиях ролей и задач.

| Задача | Лидер<br>Никита Д. | Менеджер<br>Софья А. | Дизайнер<br>Анастасия А. | Программист<br>Андрей Г. | Специалист по БД<br>Никита А. | Тестировщик<br>Артем Ш. |
| --- | --- | --- | --- | --- | --- | --- |
| Формирование команды | A | R | C | C | C | C |
| Организация коммуникации | A | R | C | C | C | C |
| Распределение ролей | A | R | R | R | R | R |
| Анализ профессиональных ролей | A | R | R | R | R | R |
| Написание эссе | A | R | R | R | R | R |
| Построение матрицы RACI | A | R | C | C | C | C |
| Оформление результатов в виде итогового отчета | A | R | R | C | C | R |

## Работа с Git по самостоятельной работе № 2

Эта матрица дополняет исходную, распределяя семь обязанностей, перечисленных в методичке. Лидер отвечает за результат всех действий, а каждый участник выполняет изменения в своих разделах и фиксирует собственный вклад.

| Задача | Лидер<br>Никита Д. | Менеджер<br>Софья А. | Дизайнер<br>Анастасия А. | Программист<br>Андрей Г. | Специалист по БД<br>Никита А. | Тестировщик<br>Артем Ш. |
| --- | --- | --- | --- | --- | --- | --- |
| Создание и настройка репозитория | R/A | C | I | I | I | I |
| Поддержание структуры папок и файлов | R/A | R | R | R | R | R |
| Написание отчётов по практическим работам | R/A | R | R | R | R | R |
| Внесение коммитов с осмысленными сообщениями | R/A | R | R | R | R | R |
| Проверка Pull Request | R/A | C | C | C | C | C |
| Слияние веток | R/A | I | I | I | I | I |
| Резервное копирование и поддержание актуальности | R/A | R | R | R | R | R |

Проверку Pull Request обычно выполняет лидер. Для Pull Request самого лидера проверку выполняет другой участник по содержанию изменений. Например, программист проверяет скрипты, тестировщик проверяет воспроизводимость и результаты проверок, менеджер проверяет полноту отчётов. Ответственность A остаётся у лидера; автор не считается независимым рецензентом своей работы.
